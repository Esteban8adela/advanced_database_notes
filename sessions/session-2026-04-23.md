## What I understood
- Transaction is a sequence of one or more SQL operations treated as a single unit.
    - COMMIT makes changes permanent.
    - ROLLBACK is the "undo" button that restores data to its last committed state.
    - SAVEPOINT allows for partial rollbacks, which is useful for complex, multi-step logic.

- Procedures allow us to move logic from the application layer into the database. 
    - By using RAISE_APPLICATION_ERROR, we can stop a transaction from completing if it violates business rules (like depositing a negative amount), ensuring the data remains "clean."

- I now understand that things that can't be "undone"—like sending an email or a push notification—should generally happen after a database transaction is committed.

- Functions and Procedures have different roles. Functions are for calculating and returning data (safe for SELECT), while Procedures are for taking action and changing data.
